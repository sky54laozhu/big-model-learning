# AI 系统的可观测性与监控 —— 出了事，你怎么第一时间知道？

> 一个全栈工程师的大模型学习笔记（三十一）

上一篇我们把力气全花在「怎么防它出事」——通道分离、动作墙、最小权限，假设被攻破也让它无害。但防护栏拦住的、没拦住的、有人正**反复试探你边界**的那些请求，你**看得见**吗？系统这一刻是健康还是正在悄悄胡说，你**心里有数**吗？

防得住是一回事，**看得见**是另一回事。这一篇讲**可观测性与监控（observability & monitoring）**：给你亲手盖起来的这套 AI 系统，装上一双眼睛。

老规矩，从你后端天天用的东西切进去。

---

## 一、锚一套你早就有的家伙：可观测性三件套

任何一个上了线的后端服务，你盯它健不健康，靠的是**可观测性三件套**：

- **日志（Logs）**：一条条离散事件。出事了翻日志找现场——「几点几分、哪个请求、报了什么错」。
- **指标（Metrics）**：QPS、延迟 P99、错误率、CPU/内存——聚合成**时间序列**画在大盘上，超阈值就**告警**。
- **链路追踪（Traces）**：一个请求穿过多少个服务、每一跳耗时多少，定位「到底是哪段慢了 / 错了」。

现在把这三件套搬到你前面 26–30 篇一路盖起来的 AI 系统上——带网关、路由、RAG、Agent 循环那一套。先问你一个直觉判断：**这三件套，哪些能原样搬过来，哪些会水土不服？**

大多数人的第一反应是：日志、指标都好办，唯独**链路追踪做不到**——模型是个黑盒，你根本追不进它脑子里。

这个直觉，一半对，一半得翻案。我们从这儿往下挖。

## 二、翻案链路追踪：黑盒进不去，但门口站得住

「追不进模型」——这半句**对**。

模型内部就是个黑盒：它为什么选了这个工具、为什么这么答、attention 在几百亿参数里怎么流动，这条「决策链路」你**追不到**，也没有意义去追（回扣第 01/24 篇「决策祛魅」：它没有规划器，就是一台 next-token 机器）。指望像单步调试代码那样看模型「想什么」，做不到。

但——你要 debug 的从来不是「模型在想什么」，而是「这个系统这一次为什么出错」。而这两件事**不一样**。

想想一个场景：线上模型干了件蠢事，吐了个离谱的 JSON、或者一本正经编了个订单号。你想查根因，可黑盒你进不去。这时候你手里**唯一还能抓的东西**是什么？

回扣整个系列的主线：**模型是黑盒，但模型外面那一圈——harness、那些确定性代码——是完全透明的**（回扣 30 承重墙、17b「if you're not the model, you're the harness」）。黑盒你进不去，但黑盒的**门口**，你站得稳稳的。

所以你要记录的，是**穿过那道门的东西**。而且是**门的两侧**：

| | 拍什么 | 为什么非拍不可 |
|---|---|---|
| **进** | 完整 Context（system / 历史 / 检索结果 / 工具返回 / 当前问句，回扣 17 六类） | 黑盒不能单步调试，只能靠「喂了什么」复盘；且它是 harness 每轮**现场拼**的、每次都不一样，不存就永远丢了 |
| **出** | 模型吐的 JSON（内容 / tool_use / stop_reason）+ token 数 | 模型这一步到底说了什么、要不要继续（回扣 18/24） |
| **harness 做了啥** | 执行了哪个工具、返回什么、走了哪条控制流分支 | 决定权在 harness，动作是它执行的（回扣 18 控制闸门） |

这里藏着一个特别容易被忽略、却最要命的点：**很多人只存「出来的 JSON」，不存「进去的 Context」。** 结果模型吐了句蠢话，你翻日志看到了那句蠢话，却**永远不知道你到底喂了它什么**——门你只拍了出去那侧，进来那侧没拍。

而模型是个纯函数 `f`（回扣 01/17：`f` 冻死，一样的输入给一样的分布）。它这次吐得离谱，**八成不是模型突然变笨，而是喂进去的那一整坨 Context 出了问题**——RAG 检索捞歪了、记忆压缩把关键那句压没了、上下文被截断了（回扣 20 garbage in / 21 检索 / 23 记忆）。**不存输入，你连「是不是喂错了」都无从查起。**

于是「链路追踪做不到」这句可以翻案了：

> **做得到。只是这条 trace 不是追进模型里，而是把模型每一次调用的「门口进出」拍成快照、串成一棵树。**

Agent 循环转 5 圈，就是 5 个这样的节点连起来（回扣 24 loop）；Orchestrator 派出去的子 agent，就是树上分出去的枝（回扣 25 编排）。一条完整的 trace，就是这一次任务里**所有跨越模型边界的进出记录**连成的图。

![链路追踪在 LLM 系统里的样子：追不进黑盒，就拍黑盒门口的进出。画面中央一个深色实心方块代表「模型（黑盒）」，方块上标「内部追不进·也没必要（回扣 01/24 决策祛魅）」。方块左侧一个大箭头指入，标「进：完整 Context —— system / 历史 / 检索结果 / 工具返回 / 当前问句」；右侧一个大箭头指出，标「出：JSON（内容 / tool_use / stop_reason）+ token 数」。方块正下方一条虚线连到一个「harness 记录器」的图标，标「门口两侧都拍照 + 记录 harness 执行了哪个工具、走了哪条分支」，并特别用红字标注「最易漏：只拍『出』不拍『进』→ 模型说了蠢话你却不知喂了它什么」。画面下半部画一棵 trace 树：根节点「一次任务」向下连出「调用①→工具→调用②→工具→调用③(end_turn)」一条主链，其中调用②旁边分叉出两个并行的「子 agent」枝（回扣 25 编排），每个节点都画成一个小方块标「进/出快照」。底部一行结论「trace = 所有跨越模型边界的进出，串成一棵树」。](assets/img/31-trace-two-sides.svg)

顺带说一个和后端的差别：后端一个 trace 的 span 通常很轻，只记 `{名字, 耗时, 状态码}`，你极少把整个请求体、响应体都塞进去。但 LLM 的 span **必须扛得住重**——完整的 prompt、完整的 completion、token 数、**还有模型版本**（回扣 29 静默升级，凶手可能就是它）。因为黑盒你只能靠这些进出快照来复盘，**省不得**。

不过「省不得」有两条边界，别读成「无脑全量、永久存」：

- **成本**：完整快照（尤其带 RAG 长上下文那种）在规模下，自身的存储 / 留存开销可能**反超推理成本**——别一边通篇回扣第 28 篇教读者省 token，一边对最重的这坨快照开无限口子。分级来：热数据留全量，冷数据采样 / 压缩 / 限留存期。
- **隐私**：prompt / completion 里裹着用户 PII、密钥、他人订单，无差别整坨落盘、长期留存，等于亲手自建一个高价值泄露面和合规（GDPR / 数据留存）雷区。落盘前该脱敏、设留存期、收紧访问权限——**观测库本身，就是第 30 篇说的那种「高价值数据目标」**，别让你装的这双眼睛反倒成了新的攻击面。

## 三、指标：老盘子搬家，加几样 LLM 独有的新菜

三件套里的另外两件——日志几乎原样搬（多存 prompt/completion 而已），重点看**指标**。你原来大盘上那些（延迟、错误率、QPS）照用，但 LLM 系统会给你添几样后端大盘上**压根没有**的新指标，而且连老指标都会**水土不服**。

| 指标 | 老 / 新 | LLM 的拧巴处 |
|---|---|---|
| **延迟** | 老，但要拆 | 流式下裂成两个数：**TTFT 首 token 延迟**（回扣 13 prefill / 28 流式）+ **总生成时长**。盯一个均值会骗你——首 token 很快、后面很慢，用户体感完全不同 |
| **token 用量** | **新** | 后端没有「token」概念，这是**成本轴**（回扣 28 成本工程）。还要拆**输入 / 输出 / 缓存命中**分档计费，一个笼统的数看不出钱花哪了 |
| **错误率** | 老 | 大坑，见下一节 ↓ |
| **缓存命中率** | 半老 | 光看命中率不够，得同时盯**错误命中率**——语义缓存返回个近义但意思相反的答案（回扣 28 退款 / 不退款），命中了反而更糟 |
| **各模型调用占比** | **新** | 路由是否漂移的眼睛（回扣 26/27）。突然全涌向 Opus = 成本要爆；某个模型占比骤然归零 = **先查自家**路由规则改动 / 鉴权失败 / 熔断跳闸（回扣 28），排除后再怀疑厂商侧变更（回扣 29） |

这几样搭起来，你的成本和性能就看得见了。但——

## 四、大盘全绿，系统却在胡说：`200 ≠ 对`

摆个场景。某天线上，你这张大盘**全是绿的**：延迟低、错误率 0、token 便宜、缓存猛命中、各模型占比正常。老板问系统健不健康，你看着满屏绿灯，说「很健康」。

结果客服那边炸了：模型这一整天都在**一本正经地胡说**——答非所问、编造订单号、甚至被人套出了不该说的话。

问题来了：**这种「坏」，为什么你大盘上一个指标都没报警？**

因为后端的健康信号，建立在一条铁律上：**`HTTP 200 = 成功`**。你的错误率大盘之所以能忠实代理「系统好不好」，是因为在后端世界里，「没抛异常」基本就等于「干对了」。

**可这条铁律在 LLM 系统里塌了。** 模型可以返回一个**完美的 HTTP 200、一段合法的 JSON、极低的延迟、极省的 token**——而内容**整个是错的**。它「成功地」生成了一段胡话。你所有的技术指标都会显示绿灯，因为从**机器的视角**看，这次调用**毫无问题**。

这正是第 22 篇那堵墙、第 29 篇那句「`assertEquals` 失效」的线上版：

> **`200 ≠ 对`。** 「跑通了」和「答对了」，在 AI 系统里是两件事。

![大盘全绿、系统却在胡说：技术指标看不见质量。画面上半部一排五个绿色圆点指标灯，依次标「延迟 ✓ 低」「token ✓ 省」「错误率 ✓ 0」「缓存 ✓ 命中」「模型占比 ✓ 正常」，上方标题「机器视角：这次调用毫无问题」。上半部右下角画一个 HTTP 响应框，标「200 OK · 合法 JSON · 低延迟」，配绿色对勾。画面正中一道横向裂缝把上下劈开，裂缝上压一行大字「200 ≠ 对」。画面下半部画模型输出的一句话气泡「您的订单号是 #8848-XY，已退款 ¥299」，旁边一个红色叹号标「编造 · 答非所问 · 被套话」，下方标题「人的视角：一整天都在胡说」。画面最右侧竖着画一根被画成灰色虚线、明显缺失的坐标轴，标「质量 / 正确性 —— 大盘上没有的那根轴」，配橙色警告三角。底部一行结论「后端铁律『HTTP 200 = 成功』在 LLM 系统里塌了：技术指标全绿 ≠ 答得对」。](assets/img/31-green-but-wrong.svg)

你少的，是一整根轴——**质量 / 正确性**。延迟、token、错误率都是**机器自己能算**的；「答得对不对、好不好」不是。这根轴，是 LLM 可观测性和传统监控**根本性的分野**。

## 五、质量测不了当场，那怎么「看见」它？

难就难在：前面那五个指标，一个请求过来机器当场读数就有。可「答得对不对」——回扣第 22 篇——**不是 `assertEquals` 能判的，是一片语义区域、有程度高低**。更要命的是**线上**这个场景：

- 你**没有标准答案**对照（用户真问题千奇百怪，哪来的黄金答案）；
- 你**不可能给每条线上请求都叫一个 LLM 裁判来打分**（回扣 22/29：成本扛不住，而且裁判本身也是会抖的模型）。

所以「答得对不对」这根轴，线上**没法直接测**。那怎么办？答案分两档。

**第一档：代理指标（proxy metrics）——用用户的行为反推质量。**

质量测不了，但**用户满不满意，会从行为里漏出来**，而这些行为你埋点抓得到（你在第 29 篇灰度那段已经用过这一招）：

- **点踩率 / 点赞率**：用户直接告诉你好不好；
- **追问率 / 重问率**：一句话没答到点上，用户会换个说法再问一遍；
- **转人工率**：AI 搞不定，用户点了「转人工」——这是**最强的失败信号**；
- **会话放弃率**：问一半直接走人；
- **复制答案率**：把答案抄走了——**正向**信号，说明有用。

锁一个性质进去：它们是**代理**，不是真值。用户点踩可能只是心情差，追问可能是想到了新问题——**每个信号都带噪声**。所以代理指标只能看**聚合趋势**（转人工率这周从 3% 翘到 9%），不能拿单条当判决。它的价值是「**便宜、准实时、机器白算**」，代价是「**糊、滞后、不告诉你为什么**」。

**第二档：采样离线精判——补代理指标「糊」的短板。**

代理指标只能告诉你「大概是变差了」，判不了「差在哪、差多少」。补法是：**采样一小撮线上流量**（比如 1%），把这些真实请求**离线、异步**地丢给第 22 篇那套 **LLM 裁判**（faithfulness / 答案相关性那类**无参考打分**，不需要预存黄金答案，回扣 22）去精判。不在热路径上，不影响用户，成本可控，又能拿到**接近真值**的质量分。

两档搭配着用：**代理指标（便宜、实时、糊）盯全量趋势 + 采样离线精判（贵、滞后、准）定期体检。**

## 六、闭环：烟雾报警器 + 案发现场

现在把前面搭的两半合起来，这就是可观测性的**经典闭环**——一根指标翘尾，你怎么顺藤摸到根因。

- **指标（含代理指标）= 烟雾报警器。** 它告诉你「有东西烧起来了」（转人工率突然翘尾、错误率飙高、成本异常），**聚合、准实时**，但它**不告诉你哪儿烧的、为什么烧**。
- **链路追踪（第二节那棵门口进出树）= 案发现场。** 报警响了，你从聚合大盘**下钻**到那一条条具体的 trace，翻开门口两侧——**进去的 Context 是什么**（检索捞歪了？记忆丢了？回扣 20/21/23）、**模型吐了什么**、**harness 走了哪条分支**——定位到根因（哦，是这批请求的 RAG 检索全命中了一篇过期文档 / 哦，是有人在这里注入，回扣 30）。

> **报警（metrics）→ 下钻（traces）→ 现场取证（logs + 进出快照）→ 定位根因。**

这条链，把三件套焊成了**一套东西**：指标负责「**发现异常**」，追踪负责「**缩小范围**」，日志/快照负责「**还原真相**」。缺了输入快照那一环（第二节反复强调的），这条链就断在最后一步——你知道出事了，却复盘不出为什么。

## 七、观测数据的第二重身价：评估飞轮的进料口

到这儿，「看见问题」的闭环齐了。但观测数据还有**第二重身价**，能把这一篇拔高一层。

那些被**点踩的、转人工的**对话，除了当场给你报警——**它们本身就是金矿**。想想第 22 篇的黄金评估集、第 29 篇的 CI 回归闸门是怎么来的：都得有人攒「典型 case」。而线上这些**翻车实录**，就是天上掉下来的、**真实分布**的典型 case。

于是闭环再套一层：

> **线上翻车（点踩 / 转人工）→ 捞出来清洗 → 收进黄金评估集（回扣 22）→ 变成下次发版的 CI 回归用例（回扣 29）→ 挡住同类问题再次上线。**

**生产环境的翻车，变成了明天的测试用例。** 可观测性就不只是「看大盘」了——它是**评估飞轮的进料口**。第 29 篇说「离线评估集是死的、真实分布更野」，这里正好补上：真实分布的野样本，就从线上观测**源源不断地流回**评估集。飞轮转起来，系统才能越跑越稳。

## 八、安全可观测性：看得见有人在敲门

回到开篇 Blog 30 埋的那个钩：**护栏拦住的、没拦住的、有人正反复试探边界的——你看得见吗？**

第 30 篇解决的是「**挡不挡得住**」，这一节解决「**看不看得见有人在攻**」。这是安全的另一半，而且它就是可观测性的一个专门切面。要盯的指标：

- **越狱 / 注入检测命中率**：入口那道注入检测软护栏（回扣 30）每天拦下多少次、命中率在涨还是在跌；
- **被拦动作率**：harness 动作墙（回扣 30 承重墙）拦下了多少次危险动作（想删库、想越权查别人订单）——**这个数突然飙高，说明有人正在系统地试探你的动作边界**；
- **按来源的异常**：某个 IP、某个 user 突然高频调用、频繁触发拦截、专挑危险工具——这是滥用 / 攻击的典型画像（回扣 28 按来源熔断，那时是为了拦，这里是为了**看见**）。

有一点得说清楚，免得和第 30 篇打架：**「看得见有人在攻」本身不等于「挡住了攻击」。** 判「这句是不是越狱」大多还是第 30 篇那种 **(b) 型语义活**——会抖、会漏。真正挡住攻击的，仍是那道确定性的**动作墙**。安全可观测性的价值不在「拦」，在**看见**：

- **早发现**——攻击刚开始试探就报警，而不是等出了事故才知道；
- **限爆炸半径**——发现某来源在攻，可以及时按来源限流 / 熔断（回扣 28）；
- **事后取证**——真出了事，靠 trace 里的进出快照还原「他到底怎么绕进来的」，补上那道墙。

**给系统装眼睛，也包括装一双专门盯「有没有人在敲门」的眼睛。**

## 九、收口：先能度量，才谈改进

第五阶段问的是「怎么把 AI 系统的架构搭对」。这一篇给的是**可观测性**这根支柱。串一遍脉络：

> 后端三件套搬家（logs / metrics / traces）→ **链路追踪翻案**：追不进黑盒，但拍得下黑盒**门口两侧**的进出（尤其别漏「进」，回扣 20 garbage in）→ 指标里加 LLM 新菜（token / 模型占比）、老指标要拆（TTFT）→ 但大盘全绿也可能在胡说，**`200 ≠ 对`**，缺了**质量轴**（回扣 22/29）→ 质量线上测不了当场，靠**代理指标 + 采样离线精判**看见它 → **烟雾报警（metrics）+ 案发现场（traces）** 闭环下钻根因 → 翻车实录反哺**评估飞轮**（回扣 22/29）→ 再装一双盯攻击的眼睛（回扣 30）。

**harness 暗线收口**：可观测性是**柱子三「驯服不确定性」的又一次落地**——你没法让那个会抖的零件不抖，但你能给它**装上仪表盘**，让它每一次抖动都**看得见、可追溯、能反哺**。

再往深一层，它和第 18、29 篇**同构**，只是尺度不同：

- 第 18 篇：单次调用尺度——schema 校验 + 重试，兜住**一次**输出；
- 第 29 篇：发布尺度——回归闸门 + 灰度，兜住**一次**改动；
- 第 31 篇：**运行尺度**——持续观测 + 告警 + 反哺，兜住**每一天的线上运行**。

三个尺度，同一个动作：**用确定的手段，兜住会抖的零件。**

最后回到全卷那句话，这次它有了新的落点：

> **可靠，不来自一个更聪明的模型；来自模型外面那圈确定性的设计——以及在那圈设计上，装好的每一只眼睛。**

**你没法凭空「改进」一个你看不见的系统。先能度量，才谈改进。** 可观测性，就是让 AI 系统从「能跑」走向「可持续变好」的那个前提。

## 小结

- **核心直觉（后端迁移）**：可观测性三件套（Logs / Metrics / Traces）照搬，但每一件到 LLM 系统都要改造。
- **链路追踪翻案**：追不进模型黑盒（回扣 01/24 决策祛魅），但模型外面那圈 harness 是透明的——trace = 把模型每次调用的**门口两侧**（进 = 完整 Context / 出 = JSON + token / harness 做了啥）拍成快照串成树（回扣 24/25）。**最易漏：只存「出」不存「进」**，模型说了蠢话却查不出喂了它什么（回扣 20 garbage in）。LLM 的 span 比后端重，要扛完整 prompt / completion / 模型版本——但「省不得」有两条边界：分级留存控成本（回扣 28）、落盘前脱敏 / 限留存 / 收紧访问，因为观测库本身就是高价值数据目标（回扣 30）。
- **指标**：新增 token 成本（回扣 28，拆输入 / 输出 / 缓存）、各模型占比（路由漂移 + 静默升级，回扣 26/29）；老指标要拆（延迟 → TTFT + 总时长，回扣 13/28）；缓存要同时盯错误命中率（回扣 28）。
- **质量轴（本篇分野）**：`HTTP 200 = 成功` 这条后端铁律在 LLM 里塌了——模型能返回完美的 200、合法 JSON、内容却全错。**`200 ≠ 对`**（回扣 29 assertEquals 失效 / 22 那堵墙）。技术指标全绿 ≠ 答得对，缺的是**质量 / 正确性**这根轴。
- **质量线上怎么看见**：测不了当场（没黄金答案 + 不能每条叫裁判，回扣 22/29）→ ① **代理指标**（点踩 / 追问 / 转人工 / 放弃 / 复制，回扣 29 灰度），是代理非真值、只看聚合趋势；② **采样离线精判**（抽 1% 流量异步丢给 22 篇裁判），补代理指标「糊」的短板。
- **经典闭环**：Metrics（含代理指标）= **烟雾报警器**（发现异常，聚合准实时，不说为什么）+ Traces = **案发现场**（下钻单条、翻门口两侧找根因，回扣 20/30）。报警 → 下钻 → 取证 → 根因，三件套焊成一套。
- **评估飞轮进料口**：线上翻车实录（点踩 / 转人工）→ 收进黄金评估集（回扣 22）→ 变 CI 回归用例（回扣 29）。生产翻车 = 明天的测试用例，真实分布的野样本源源不断回流。
- **安全可观测性**（回扣 30 钩）：越狱 / 注入检测命中率、被拦动作率（突然飙高 = 有人在系统试探边界）、按来源异常（回扣 28）。「看得见」不等于「挡住了」——挡靠动作墙，看的价值在**早发现 / 限爆炸半径 / 事后取证**。
- **harness 暗线**：可观测性 = 柱三驯服不确定性的落地（给会抖的零件装仪表盘），和第 18（单次校验）、29（发布回归）同构，只是尺度不同（运行尺度）。**先能度量，才谈改进**——可靠不来自更聪明的模型，来自模型外那圈确定性设计上装好的每一只眼睛。
